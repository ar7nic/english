# Тест з англійської граматики

Офлайнова PWA для самодіагностики граматики A2 → B2. Особистий інструмент:
бекенду, акаунтів і мережевих запитів немає, усі дані лишаються в `localStorage`
браузера. Інтерфейс українською, питання англійською.

Зібрано з артефакту `grammar-diagnostic.jsx` (лежить у корені як довідка —
можна видалити). Логіку добору й підрахунку винесено в модулі без React, UI
розкладено по екранах.

## Запуск

```bash
npm install
npm run dev          # http://localhost:5173
npm run build        # збірка в dist/
npm run preview      # перевірка збірки на :4173 (тут працює service worker)

npm test             # юніт-тести (vitest)
npm run test:e2e     # e2e (playwright; сам зробить build + preview)

npm run icons        # перегенерувати іконки PWA
npm run fonts        # перезабрати шрифти з Google Fonts у src/fonts
```

Перед першим `npm run test:e2e`: `npx playwright install chromium`.

`npm run fonts` — єдина команда, якій потрібна мережа, і вона робить це на
етапі підготовки. Результат (`src/fonts/*.woff2` + згенерований
`src/fonts.css`) комітиться, тож збірка, тести й деплой мережі не потребують.

## Структура

```
src/
  data/questions.js      Q, Q2, Q3, Q4, SUITES, POOL — 320 питань, 20 тем
  lib/selection.js       QID, TEST_LEN, buildSelection, buildProbes, markUsed
  lib/scoring.js         norm, isRight, estimateLevel, scoreAttempt, LEVELS
  lib/storage.js         async-адаптер поверх localStorage + JSON-обгортки
  lib/history.js         історія спроб: запис, читання, імпорт, динаміка
  lib/format.js          дрібниці для показу: відсотки, дати, множина
  components/            Intro, Question, Report, History
  App.jsx, main.jsx, styles.css
  fonts.css, fonts/      локальні Archivo та IBM Plex (npm run fonts)
tests/unit/              vitest — без рендеру, тільки lib/ і data/
e2e/                     playwright — по зібраному додатку
public/                  іконки (manifest і sw генерує vite-plugin-pwa)
scripts/                 генерація іконок і забір шрифтів
.github/workflows/       тести → збірка → GitHub Pages
```

`lib/` і `data/` не імпортують нічого з React — саме тому вони тестуються
без DOM і без рендеру.

## Пул питань і ротація

Пул — **320 питань**: 20 тем × 4 слоти («тема + рівень + тип») × 4 варіанти.
Базовий тест бере по одному питанню з кожного слоту, тобто **80**.

Вибір не випадковий: береться варіант із найдавнішим значенням у `usage`,
серед однаково давніх — випадково. Тому **чотири спроби поспіль ідуть без
жодного повтору**, а на п'ятій цикл починається спочатку.

Питання ідентифікуються стабільним `QID` виду `тема-рівень-тип-номер`, а не
індексом у масиві: нові питання можна дописувати в кінець `data/questions.js`,
історія показів від цього не збивається.

Показані питання фіксуються **один раз — у момент появи звіту**. Перервана
спроба ротацію не витрачає.

## Адаптивна фаза

Після базових 80 питань теми з результатом 2 з 4 і гірше (`WEAK_THRESHOLD`)
отримують ще по 3 питання (`PROBES_PER_SUITE`), максимум 5 тем
(`MAX_WEAK_SUITES`) — до 15 додаткових. Уточнення беруться з невикористаних у
поточній спробі й теж проходять через ротацію.

**Рівень рахується тільки з базових 80 питань** — інакше кожен, у кого є
слабкі теми, отримував би занижений рівень через додаткові складні питання.
**Розбивка по темах** рахується з базових плюс уточнення.

Пороги (a, b, c — відсотки правильних по A2, B1, B2), перше збіжне правило
спрацьовує:

| правило | рівень |
| --- | --- |
| a ≥ 85 і b ≥ 80 і c ≥ 75 | B2+ |
| a ≥ 80 і b ≥ 75 і c ≥ 55 | B2 |
| a ≥ 80 і b ≥ 60 | B1+ |
| a ≥ 70 і b ≥ 45 | B1 |
| a ≥ 55 | A2+ |
| інакше | A2 |

Жодних LLM-викликів: підрахунок детермінований і працює офлайн.

## Сховище

Три незалежні ключі в `localStorage`:

| ключ | що тримає | коли чиститься |
| --- | --- | --- |
| `grammar-diagnostic:progress:v1` | поточне проходження: `sel`, `probes`, `answers`, `idx`, `started`, `done`, `attemptId` | кнопкою «Нова спроба» |
| `grammar-diagnostic:usage:v1` | історія показів `{ run, used: { qid: run } }` | ніколи автоматично |
| `grammar-diagnostic:attempts:v1` | до 50 завершених спроб | кнопкою «Стерти історію» |

«Нова спроба» **не** чіпає `usage` — інакше ротація зламається і питання
почали б повторюватися. «Стерти історію» не чіпає ні `usage`, ні прогрес.

Запис прогресу — з паузою 800 мс, не на кожне натискання клавіші. Стан запису
видно в рядку над карткою: `збереження…` → `збережено`, або
`⚠ не зберігається`, якщо сховище відмовило (приватне вікно, вичерпана квота).
Помилки запису не глушаться — у звіті з'являється попередження скопіювати
текст, перш ніж закривати вкладку.

Запис спроби в історію: дата, оцінений рівень, відсотки по A2/B1/B2, результат
по кожній з 20 тем і список помилок (`qid`, дана відповідь, правильна
відповідь). На екрані «Історія» — динаміка по темах, повторювані помилки,
експорт і імпорт усієї історії у JSON.

Імпорт зливає, а не затирає: спроби з однаковим `id` не дублюються, биті
записи відкидаються з підрахунком, а зрозуміла помилка («Це не JSON-файл»,
«У файлі немає списку спроб») показується просто на екрані. Файл експорту —
`{ app, version, exportedAt, attempts }`, але імпорт приймає і голий масив.

## PWA

`vite-plugin-pwa` у режимі `generateSW` / `autoUpdate`: маніфест і service
worker збираються з конфігу у `vite.config.js`. Precache охоплює js, css, html,
png, svg **і woff2** — без останнього офлайн виглядав би іншим шрифтом.
Жодного `runtimeCaching` на зовнішні хости немає: додаток нікуди не ходить.

Іконки 192 і 512 (плюс maskable) генерує `scripts/gen-icons.mjs` — ручний
растеризатор PNG на `node:zlib`, щоб не тягнути `sharp` заради трьох статичних
файлів. `display: standalone`, `start_url` і `scope` відносні, тому додаток
однаково встановлюється і з кореня домену, і з `/<репо>/`.

Шрифти локальні. `npm run fonts` забирає з Google Fonts підмножини latin і
cyrillic (українська вкладається в U+0400-045F та U+0490-0491), кладе woff2 у
`src/fonts` і генерує `src/fonts.css`. Archivo кириличної підмножини не має,
тому заголовки українською падають на системний гротеск — рівно так само, як
це було з `@import` у вихідному артефакті.

Що стережуть тести: `жодних зовнішніх запитів у рантаймі` (перехоплює всі
запити сторінки і вимагає порожній список чужих origin) і
`додаток відкривається без мережі` (офлайн-перезавантаження + `document.fonts`
+ проходження питання без мережі).

### Встановлення на пристрій

Автоматично перевіряється те, що можна перевірити машинно: маніфест
віддається, іконки — справжні PNG заявлених розмірів, service worker
контролює сторінку, офлайн-режим працює. **Реального встановлення на Android
Chrome і на Windows я не перевіряв — фізичних пристроїв тут немає.** Ручний
чекліст після першого деплою:

- Android Chrome: меню → «Встановити застосунок»; запуск має бути без
  адресного рядка, іконка на робочому столі — не скриншот сторінки.
- Windows Chrome/Edge: значок встановлення у правій частині адресного рядка;
  вікно відкривається окремо, у списку застосунків є «Граматика».
- В обох випадках: увімкнути режим польоту і відкрити застосунок — має
  запуститися з тим самим шрифтом і збереженим прогресом.

## Екрани

- **Intro** — опис, лічильник пройдених спроб, кнопка старту, вхід в історію.
- **Question** — питання, стрічка прогресу з переходом до будь-якого питання,
  банер паузи посередині, банер входу в адаптивну фазу.
- **Report** — рівень, відсотки по рівнях, теми від слабшої до сильнішої,
  розбір усіх помилок із поясненнями, звіт простим текстом із копіюванням.
- **History** — список спроб, динаміка по темах між спробами, повторювані
  помилки, експорт та імпорт JSON.

Під час проходження тема й рівень питання не показуються: тема називає
правило, яке перевіряється, а рівень підказує, чи потрібна складніша форма.
І те, і те з'являється тільки у звіті — біля розбору помилок.

Копіювання звіту йде трьома шляхами по черзі: `navigator.clipboard` →
`document.execCommand('copy')` → виділення тексту з підказкою скопіювати
вручну. У вбудованих і мобільних браузерах перші два часто недоступні.

## Деплой

`.github/workflows/deploy.yml` на пуш у `main`: юніт-тести → e2e (з реальним
chromium) → збірка → GitHub Pages. Деплой не стартує, поки тести не пройшли;
якщо e2e падає, звіт Playwright підвантажується як артефакт.

Pages віддає проєкт із підпапки, тому збірка в CI іде з
`BASE_PATH=/${{ github.event.repository.name }}/`, а `vite.config.js` кладе це
в `base`. Без цього — біла сторінка і 404 на асетах. Локально `BASE_PATH` не
заданий, тож `base` лишається `/` і `npm run preview` працює як завжди.

У налаштуваннях репозиторію треба один раз виставити **Settings → Pages →
Source: GitHub Actions**.

## Як додати питання

Дописати об'єкти в кінець будь-якого масиву в `src/data/questions.js`:

```js
{ s: 0, lvl: "A2", t: "mc", q: "...", o: ["a","b","c","d"], a: 1, note: "..." }
{ s: 0, lvl: "A2", t: "gap", q: "...", accept: ["is sleeping"], show: "is sleeping", note: "..." }
```

`npm test` перевіряє інваріанти: рівно 4 варіанти на слот, по 16 питань на
тему, коректні індекси й поля, `show` серед `accept`, відсутність дублікатів.
Якщо додати п'ятий варіант у слот — тест впаде, і це навмисно: тоді треба
свідомо міняти й очікування «4 спроби без повторів».
